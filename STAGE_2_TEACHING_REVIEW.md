## Lesson 1: Time, Space & Big-O — 11 November 2026

**Purpose and prerequisites.** Starts with scaling a record-processing tool and deciding which work grows before buying hardware or adding workers. Explicitly links loops/stopping conditions, list references and Stage 1 capstone practice. Objectives require a declared size/case/model, derivation, bounds, storage accounting and scoped measurement. Starting Stage 2 development does not award Stage 1 practical mastery.

**Definitions and mechanism.** Defines algorithm/instance, n, a cost model, selected-event counts and asymptotic behavior before notation. Distinguishes fixed-size/word operations from long strings, unbounded integer-bit costs and I/O. Separates a particular input case from O/Ω/Θ; neither Θ nor Ω is mislabeled as average/best case. Full nonnegative eventual bound definitions include constants independent of n and a threshold. A 3n+7 example proves tight linear growth with explicit constants; linear functions' loose quadratic upper bound and n²'s failure to be O(n) expose misuse.

**Worked reasoning.** Search on 0…7 derives first/last/absent counts 1/8/8 and empty count 0, with first matching position p giving p+1. The uniform-present expectation (n+1)/2 states its distribution assumption. Unordered pairs are explicitly listed at n=4; n(n−1)/2 is derived by counting ordered pairs twice, verified at n=8 as 28, and bounded between n²/4 and n²/2 for n≥2. Repeated halving derives floor(log₂ n)+1 for positive n, zero for n=0, and includes the final 1→0 update. Numeric magnitude versus encoded bit length is explicitly distinguished. Sequential scans, fixed inner loops, rectangular nm bounds and validation-plus-query composition prevent syntax-based classification.

**Meaningful experiments.** Operation lab changes one of four kernels, size 0/1/2/4/8/16 and search case. Predictions check the exact named event; changed inputs reset prediction/replay. It highlights visited list positions, separates internal counts/result/output slots, and shows return without adding another selected event. Every kernel/size/case result across 102 combinations was compared with actual Python. Playback is pedagogical, not benchmarking. Growth lab supplies 1, log₂ n, n, n log₂ n, n² and 2ⁿ mathematical values, a selected-curve SVG and numeric cards. Vertical rescaling is explicit; visible axis-range prose was added for mobile readability. No extrapolated runtime, execution of an exponential workload or proof from a small plot is claimed.

**Space reasoning.** Defines input/output/other auxiliary space, peak simultaneous storage and conventions. Filtering n values produces k references: output-inclusive extra space Θ(k+1), worst-case Θ(n), other auxiliary space Θ(1) in the declared word model. Actual list capacity/bytes and arbitrarily large Python counters are outside those logical-slot statements. Count-only filtering answers a different output requirement. Counting quadratic pair visits need not retain quadratic output; materializing pairs would. Generator construction is not equated with full consumption. Recursion/amortized allocation remain later mechanisms, not unexplained assertions here.

**Timing and failure misconceptions.** Canonical standard-library Python files are imported directly for display. measure_search times plain absent-target search at sizes 128/1024/2048 with 3 samples of 100 calls, excluding input construction but including function/callable overhead. It reports all seconds-per-call samples, minimum, scope and interpreter/version. timeit's automatic-GC default and workload/environment variability are explicit. Tests assert correct scope and finite nonnegative samples, not machine-specific ratios/winners. Illustrative mathematical costs 100n versus n² show finite-size constants without pretending to be measured algorithms. Selected event counts omit bookkeeping; zero counted pair visits does not imply zero running time.

**Independent transfer.** Two scans versus n-by-m work require separate counters and boundary cases, with fixed m=3 versus m=n explanations. A validation-plus-query claim requires accounting for the hidden pass. A memory-budget task changes the predicate and requires all-match/no-match storage evidence while preserving caller output requirements. Reference tests execute separate rectangular/two-pass derivations. Knowledge-check completion supplements these practical artifacts rather than proving mastery.

**Accuracy.** Reviewed MIT 6.006 Spring 2020 Recitation 1 definitions/cost-model notes and official Python 3.12 timeit documentation. Explanations and numeric derivations use the declared model; real programs verified locally on CPython 3.12.3. No universal complexity claim for unbounded arbitrary Python operations, production pipeline latency or cross-platform timing is made.

## Lesson 2: Arrays and Dynamic Storage — 27 November 2026

**Purpose/sequence.** Connects playlist/search-result sequence requirements to storage operations after Lesson 1's cost models, Stage 1 classes/invariants and aliasing. Learners explain size/capacity, derive shifts, implement explicit backing storage, prove a sequence bound and account for peak storage/failures. Stable position versus stable item identity is distinguished.

**Meaning and layout.** Defines static/dynamic arrays, live prefix/spare slots and 0≤n≤C before internal mechanics. The illustrative fixed-width formula base+i×width yields 512+3×8=536; bounds still determine whether an index is live. Virtual slot contiguity is not equated with adjacent physical RAM, and CPython reference slots are distinguished from packed fixed-width payload values. No pointer/address measurement or exact CPython capacity policy is claimed.

**Mechanism and worked reasoning.** Inserting at i shifts n−i references right-to-left to avoid overwriting unread sources; removal saves the result, shifts n−i−1 left and clears the former tail. Examples derive [10,90,20,30] from insertion at 1 and [10,30,40] from removal at 1, with independent counts. Canonical DynamicArray uses fixed-length preallocated Python backing lists without their append/insert/pop methods, a private unused sentinel (None is valid data), strict exact/nonnegative indices and no automatic shrinking. Allocation/copy precedes replacing the backing reference; allocation failure is not hidden. Shifts/copies preserve payload identity. Snapshot is Θ(n); invariant scans are Θ(C), not necessarily Θ(n) after removals. This distinction was corrected during teaching review and checked by instrumenting actual backing reads. Debug scans are excluded from kernel counters.

**Experiment.** Movement lab changes append/insert/pop/invalid index, full/spare occupancy and first/middle/last positions. Numeric fixtures and transient buffer states are labeled as a bounded model. It separates initialized slots, growth copies, shifts, stores and clears, with written numeric prediction feedback. Intermediate old/new buffers show coexisting storage; completed method boundaries, rather than each transient shift, carry the logical invariant. All 24 fixture combinations match actual Python final size/buffer/counters/peak/result. Rewind changes inspection state only, not real memory or a learner file.

**Amortized derivation and counterexample.** For m≥1 appends from empty, largest doubling capacity C<2m. Copies total C−1<2m, initialized slots 2C−1<4m and stores m; selected units total <7m. Ordinary loop/metadata work has the same aggregate order under the stated model. This is a deterministic sequence bound, not random-input averaging or constant per-call latency. At m=8 the components 15+7+8 give 30; the fifth append alone costs 13 and peaks at 12 coexisting slots. Exact-fit +1 growth has m²+m units (72 at eight appends), exposing quadratic aggregate work. At small m=3 doubling costs 13 versus 12 for +1, preventing a false every-prefix speed claim. Repeated front insertion still incurs m(m−1)/2 shifts despite linear growth-copy work. The second lab exposes cumulative/single-call totals, capacities and peak slots with a contained, keyboard-focusable horizontal table.

**Failures/limits.** Invalid types/indices fail before allocation/mutation. New-buffer allocation failure preserves the old backing/state/counters. This is not a universal transaction guarantee for all interpreter failures, concurrent mutation or finalizer reentrancy. Removed references are cleared; capacity can remain high without shrinking. Peak coexisting buffers, final capacity, logical payload count and actual process bytes are separate. Shrink hysteresis requires a new sequence analysis and is not left as a hidden reference implementation. Python's actual allocator/growth factor is not simulated. Source preconditions disallow passing the private sentinel or mutating internal storage.

**Transfer.** A stable remove_all compaction task changes the algorithm: [10,20,10,30] removing 10 yields [20,30], count 2, retained order/capacity and cleared tail, with one visit pass rather than repeated front removal. Empty/no/all matches, None and aliases require independent expectations. A second task separates quadratic front-shift totals from linear growth-copy totals. Reference tests independently check compaction expectations and both sequence derivations; learner implementation/explanation remains separate from the quiz.

**Accuracy.** Reviewed MIT 6.006 Spring 2020 Lecture 2 dynamic-array/amortized notes and official Python 3.12 list-implementation FAQ. Canonical standard-library files live in examples/stage-2-arrays and are imported directly for lesson display. Actual execution is local CPython 3.12.3. This lesson does not certify a particular allocator, byte footprint, production latency or other platform.
