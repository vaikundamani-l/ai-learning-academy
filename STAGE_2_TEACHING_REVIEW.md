## Lesson 1: Time, Space & Big-O — 11 November 2026

**Purpose and prerequisites.** Starts with scaling a record-processing tool and deciding which work grows before buying hardware or adding workers. Explicitly links loops/stopping conditions, list references and Stage 1 capstone practice. Objectives require a declared size/case/model, derivation, bounds, storage accounting and scoped measurement. Starting Stage 2 development does not award Stage 1 practical mastery.

**Definitions and mechanism.** Defines algorithm/instance, n, a cost model, selected-event counts and asymptotic behavior before notation. Distinguishes fixed-size/word operations from long strings, unbounded integer-bit costs and I/O. Separates a particular input case from O/Ω/Θ; neither Θ nor Ω is mislabeled as average/best case. Full nonnegative eventual bound definitions include constants independent of n and a threshold. A 3n+7 example proves tight linear growth with explicit constants; linear functions' loose quadratic upper bound and n²'s failure to be O(n) expose misuse.

**Worked reasoning.** Search on 0…7 derives first/last/absent counts 1/8/8 and empty count 0, with first matching position p giving p+1. The uniform-present expectation (n+1)/2 states its distribution assumption. Unordered pairs are explicitly listed at n=4; n(n−1)/2 is derived by counting ordered pairs twice, verified at n=8 as 28, and bounded between n²/4 and n²/2 for n≥2. Repeated halving derives floor(log₂ n)+1 for positive n, zero for n=0, and includes the final 1→0 update. Numeric magnitude versus encoded bit length is explicitly distinguished. Sequential scans, fixed inner loops, rectangular nm bounds and validation-plus-query composition prevent syntax-based classification.

**Meaningful experiments.** Operation lab changes one of four kernels, size 0/1/2/4/8/16 and search case. Predictions check the exact named event; changed inputs reset prediction/replay. It highlights visited list positions, separates internal counts/result/output slots, and shows return without adding another selected event. Every kernel/size/case result across 102 combinations was compared with actual Python. Playback is pedagogical, not benchmarking. Growth lab supplies 1, log₂ n, n, n log₂ n, n² and 2ⁿ mathematical values, a selected-curve SVG and numeric cards. Vertical rescaling is explicit; visible axis-range prose was added for mobile readability. No extrapolated runtime, execution of an exponential workload or proof from a small plot is claimed.

**Space reasoning.** Defines input/output/other auxiliary space, peak simultaneous storage and conventions. Filtering n values produces k references: output-inclusive extra space Θ(k+1), worst-case Θ(n), other auxiliary space Θ(1) in the declared word model. Actual list capacity/bytes and arbitrarily large Python counters are outside those logical-slot statements. Count-only filtering answers a different output requirement. Counting quadratic pair visits need not retain quadratic output; materializing pairs would. Generator construction is not equated with full consumption. Recursion/amortized allocation remain later mechanisms, not unexplained assertions here.

**Timing and failure misconceptions.** Canonical standard-library Python files are imported directly for display. measure_search times plain absent-target search at sizes 128/1024/2048 with 3 samples of 100 calls, excluding input construction but including function/callable overhead. It reports all seconds-per-call samples, minimum, scope and interpreter/version. timeit's automatic-GC default and workload/environment variability are explicit. Tests assert correct scope and finite nonnegative samples, not machine-specific ratios/winners. Illustrative mathematical costs 100n versus n² show finite-size constants without pretending to be measured algorithms. Selected event counts omit bookkeeping; zero counted pair visits does not imply zero running time.

**Independent transfer.** Two scans versus n-by-m work require separate counters and boundary cases, with fixed m=3 versus m=n explanations. A validation-plus-query claim requires accounting for the hidden pass. A memory-budget task changes the predicate and requires all-match/no-match storage evidence while preserving caller output requirements. Reference tests execute separate rectangular/two-pass derivations. Knowledge-check completion supplements these practical artifacts rather than proving mastery.

**Accuracy.** Reviewed MIT 6.006 Spring 2020 Recitation 1 definitions/cost-model notes and official Python 3.12 timeit documentation. Explanations and numeric derivations use the declared model; real programs verified locally on CPython 3.12.3. No universal complexity claim for unbounded arbitrary Python operations, production pipeline latency or cross-platform timing is made.
